## 结论先行

StepView 已经具备有辨识度的产品内核：**成长不是待办，而是一条能回看的路径**。自由画布、目标路径、支线、日记、完成画廊、Agent 审批、账号隔离、SQLite 迁移与备份机制，均明显强于普通原型。

目前的主要瓶颈不是“功能还不够多”，而是：

1. 新用户进入后不能在 1 分钟内稳定获得第一次价值。
2. 数据保存、失败、备份、恢复没有被清楚地呈现在界面中，信任感不足。
3. 双击、右键、拖拽点、悬停按钮等隐藏交互过多，学习成本高且难以触屏使用。
4. 中英混排、样例预填、`Coming soon`、开发者化错误信息，使产品仍像开发样机。
5. 工程后端能力已经走得很远，但品牌、分发、反馈、留存与增长闭环明显落后。

因此顺序必须是：**信任与数据安全 → 首次激活 → 核心留存 → 可分享的回顾 → 增长与商业化**。

## 不可破坏的产品红线

- [ ] **[永久红线]** 任何 Demo、模板、教程、导览、测试数据都不得自动写入、覆盖或替换用户 Board。
  - 示例只能出现在只读弹窗、独立预览/沙盒，或用户看完差异并明确确认后的导入流程中。
  - 导入前必须展示影响范围并创建可恢复快照；默认合并到新空间，不覆盖当前空间。
  - 增加自动化测试：打开/跳过/完成教程均不得调用 `updateBoard`、`saveBoard` 或等价写接口。
- [ ] 删除、清空、覆盖、恢复、导入等高风险操作必须可预览、可取消、可恢复。
- [ ] 用户的备份、导出和删除权不进入付费墙。
- [ ] 私密内容默认不上传、不公开、不进入训练；任何遥测、云同步、公开分享都需清晰告知并由用户主动开启。
- [ ] 不用连续打卡、羞辱文案、红色逾期等方式制造焦虑；允许休息、失败和绕路成为成长路径的一部分。
- [ ] 浏览器本地模式不得被描述成强安全边界；数据位置、账号隔离能力与风险必须如实说明。

## 优先级与完成定义

- **P0 / 发布阻断**：可能造成数据丢失、隐私泄露、错误账号空间、关键流程失败或严重信任损伤。
- **P1 / 0–30 天**：直接提高首次激活和第 2 周留存的核心产品工作。
- **P2 / 31–90 天**：规模化体验、工程效率、分发与自然增长。
- **P3 / 验证后**：商业化、多人协作、生态扩展等高成本方向。
- 每条任务的完成至少包括：实现、测试、用户可理解的错误/空态、必要文档、一个可观测的验收指标。
- 任何“完成”不能只以代码合并为准；产品项至少要经过 5 名目标用户可用性验证或明确的数据验证。
