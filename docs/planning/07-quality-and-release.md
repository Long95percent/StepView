## 测试与质量门禁

### 自动化测试层级

- [ ] 保留已有大量服务/逻辑测试，并按 unit / integration / contract / e2e 分类，缩短定位时间。
- [ ] 增加 React 组件测试：首次空态、建目标、加一步、编辑、删除撤销、保存失败、账号切换、备份恢复。
- [ ] 增加 Playwright Electron E2E：首次启动→真实目标→第一步→关闭→重开→数据仍在。
- [ ] 增加家庭 Web E2E：注册 capability、登录、跨账号隔离、断网重连、会话过期。
- [ ] 增加 Agent E2E fake provider，覆盖审批、拒绝、过期、撤销、断流和重复工具调用。
- [ ] 增加视觉回归：核心三屏、窄窗、深浅主题、200% 缩放、长中文/英文。
- [ ] 增加 axe、仅键盘和 reduced-motion 检查。
- [ ] 对 Board 操作、diff、merge、migration 使用属性测试/模糊测试，重点验证不丢节点、不产生悬空引用。

### CI 质量门禁

- [ ] 建立 GitHub Actions：安装锁定依赖、lint、格式检查、类型检查、测试、构建、包体积与漏洞扫描。
- [ ] CI 在 Linux/Windows/macOS 至少覆盖受支持路径；端口测试在允许监听的隔离 runner 运行。
- [ ] 任何 P0 流程失败、迁移失败、跨账号访问成功、备份恢复失败均阻断发布。
- [ ] 设置覆盖率基线和“新增代码不降低”规则，但不以追求百分比替代关键场景测试。
- [ ] 失败测试不得长期 skip；每个 quarantine 测试有负责人、原因和截止日期。
- [ ] PR 模板要求说明数据迁移、隐私、可撤销性、截图和验证步骤。
- [ ] 主分支保护：至少一次审查、CI 全绿、禁止直接推送发布标签。

### 发布前人工清单

- [ ] 新用户无历史数据完整走一遍。
- [ ] 旧版本真实副本升级并回滚一遍。
- [ ] 备份、校验、恢复和撤销各走一遍。
- [ ] 离线、服务端挂掉、磁盘满、错误 API Key 各走一遍。
- [ ] 仅键盘、读屏、触屏、小窗口各走一遍。
- [ ] 所有分享/导出检查隐私默认值与元数据。
- [ ] 安装、卸载、更新不删除用户数据，卸载前说明数据保留位置。

## 发布、安装与供应链

- [ ] 将 macOS 当前 ad-hoc 签名升级为 Developer ID 签名与公证，验证 Gatekeeper 首次安装体验。
- [ ] Windows 从 `dir` 产物升级为签名安装器；处理 SmartScreen、升级和卸载保留数据。
- [ ] 明确支持 Apple Silicon、Intel、Windows 版本和 Linux 状态；不支持的平台不要给模糊承诺。
- [ ] 每个 Release 自动生成校验和、SBOM、变更日志、已知问题和升级/回滚说明。
- [ ] 建立稳定、beta 两个通道；数据库 schema 变更先经过 beta 真实数据副本验证。
- [ ] 设计自动更新：下载校验、签名验证、更新前备份、失败回滚、用户可延期。
- [ ] 发布包不得包含 `.env`、测试密钥、用户数据、开发日志、源 map 中的秘密或不必要源码。
- [ ] 固定 Docker 基础镜像摘要的同时建立定期升级与漏洞响应流程，避免“固定”变成永不更新。
- [ ] 建立安全漏洞私下报告入口和响应 SLA。

## 每次发布的 Go / No-Go 门槛

- [ ] 所有 P0 数据、认证和隐私问题已关闭并有自动化回归。
- [ ] 新建、保存、关闭、重开、备份、恢复、撤销的黄金路径全部通过。
- [ ] 升级至少从当前两个历史版本的真实副本成功，失败可回滚。
- [ ] 桌面与家庭模式的账号隔离测试通过。
- [ ] UI 中不存在把错误伪装成空数据、把未保存伪装成已保存的状态。
- [ ] 安装包已签名/校验；依赖与镜像扫描无未接受的高危漏洞。
- [ ] 发布说明写明数据变更、备份建议、已知问题和回滚方法。
- [ ] 产品负责人能用数据回答：这次发布改善哪个用户结果，如何判断成功或回退。
