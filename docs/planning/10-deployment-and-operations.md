# 部署与运维计划

> 状态：规划草案，当前**只建议本机或可信局域网测试，不建议直接开放公网**  
> 最后整理：2026-10-19  
> 范围：本机启动、局域网内测、服务器部署、备份恢复、监控告警、升级回滚和开放门槛  
> 导航：[返回规划中心](README.md)

## 先给结论

StepView 目前的部署基础已经够用，不需要从零搭系统：已有 `web + gateway + Redis` 的 Docker Compose 栈，默认只把 Web 绑定到 `127.0.0.1:5173`，Gateway 和 Redis 都没有发布到宿主机。自己先用、再给同一可信局域网内的少量朋友试用，并不算麻烦。

真正需要认真准备的是公网阶段。推荐顺序是：

```text
本机单人自测
  -> 可信局域网朋友测试
  -> 私有服务器预演（VPN / IP 白名单）
  -> 邀请制公网 Beta
  -> 达到安全、恢复和留存门槛后再扩大开放
```

当前最合适的技术路线是**单机 Docker Compose + 单 Gateway + SQLite + Redis 缓存**。前 20–50 位邀请用户不需要 Kubernetes、微服务、托管 Redis 或提前迁移 PostgreSQL。先把数据不丢、账号不串、备份能恢复、版本能回滚做好，比扩容架构重要得多。

## “暂时不连接外网”要先区分两件事

| 目标 | 含义 | 当前是否可行 |
| --- | --- | --- |
| 不开放公网入口 | 外部互联网不能访问服务，但本机仍可下载依赖或调用模型 | 推荐，默认 Compose 已接近这个状态 |
| 完全断开互联网 | 主机没有任何入站或出站互联网连接 | 核心 Board 可用，但必须提前准备镜像和构建产物；OpenAI、Mem0 和其他远程模型不可用 |

`npm run family` 禁止自动拉取基础镜像，但构建阶段的 `npm ci` 仍可能访问 npm 源。因此，“完全断网运行”应先在联网状态准备并构建好镜像，再断网使用已有镜像启动；不能把首次构建也当成天然离线。

远程朋友无法在“不开放公网且不使用互联网”的条件下访问同一台服务。这个阶段只能让同一局域网内的朋友访问，或让远程朋友各自使用桌面版；Tailscale、WireGuard 和云服务器都属于后续的联网私测方案。

## 当前部署基础与缺口

### 已经具备

- Web 通过同源 `/api` 反向代理 Gateway，浏览器无需直接连接 `3210`。
- 默认只发布 `127.0.0.1:5173`；Gateway `3210` 和 Redis `6379` 只在 Compose 内网可达。
- 网页注册默认关闭，可以使用容器内 CLI 建号。
- 已有账号隔离、密码哈希、登录失败退避、请求体上限、API Key 加密和会话过期。
- 已有 `/api/health`、`/api/readyz`、请求 ID 和结构化请求日志。
- Web 和 Gateway 容器以非 root 用户运行，基础镜像按 digest 固定。
- SQLite 数据持久化在 `.stepview-family-data`，Redis AOF 在 `.stepview-runtime/redis`。

### 当前已确认的阻塞项

1. Compose 读取 `.env`，启动前检查读取 `.env.local`，检查结果和实际容器配置可能不一致。
2. README 要求创建 `.env`，但 `.gitignore` 没有忽略 `.env`；`.dockerignore` 也没有统一排除 `.env*`。
3. `compose.yaml` 没有把 `STEPVIEW_SECRET_KEY` 传给 Gateway，生产环境即使配置也不会生效，而是回退到数据目录内自动生成的 `secret.key`。
4. Gateway 容器健康检查仍访问 `/api/health`，没有使用能检查数据目录和数据库的 `/api/readyz`。
5. 现有 archive 能力面向单个账号，不是家庭服务器全部账号的一致性备份，也没有异地上传和恢复 CLI。
6. Nginx 追加客户端传入的 `X-Forwarded-For`，Gateway 又信任第一段地址，公网登录限流可能被伪造 IP 绕过。
7. 缺少修改密码、管理员重置密码、禁用账号、吊销全部会话和查看活跃会话等运维能力。
8. 登录令牌保存在 `localStorage`，当前 Web 又没有严格 CSP；公网前需要降低 XSS 窃取长会话的风险。
9. 登录用户可以配置任意 OpenAI-compatible Base URL，公网环境存在 SSRF、云元数据和内网探测风险。
10. 缺少生产反向代理、TLS、安全响应头、日志轮转、磁盘/备份/证书告警和可验证回滚流程。

这些问题不妨碍默认回环地址下的个人试用，但其中大部分是公网前的硬门槛。

## 阶段总览

| 阶段 | 人数与范围 | 建议时长 | 入口 | 本阶段目的 |
| --- | --- | ---: | --- | --- |
| L0 本机自测 | 仅自己 | 3–7 天 | `127.0.0.1:5173` | 验证启动、保存、重启、备份和基本可用性 |
| L1 可信局域网 Alpha | 2–5 位朋友 | 2–4 周 | 明确的 LAN IP，仅可信网络 | 验证多账号隔离、稳定性和真实使用反馈 |
| L2 私有服务器预演 | 自己和少量测试者 | 3–7 天 | HTTPS + VPN 或 IP 白名单 | 演练服务器部署、告警、备份、升级和回滚 |
| L3 邀请制公网 Beta | 5–20 人，逐步到 50 人 | 至少 2–4 周 | HTTPS，关闭公开注册 | 验证公网安全、支持成本、留存和容量 |
| L4 扩大开放 | 20–50+ 人 | 指标达标后 | 邀请或开放注册 | 验证商业化与可持续运营，再考虑扩容 |

任何阶段都不按日历自动升级；必须达到该阶段的 Go 条件才能进入下一阶段。

## L0：本机单人启动 Runbook

### 准备

- 安装并启动 Docker Desktop。
- 使用 Node.js 22 或更高版本。
- 确认 Docker 基础镜像已经准备好；缺失时需要在允许联网的环境执行一次显式拉取。
- L0 不创建 `.env`，保持默认回环绑定和默认关闭注册。
- 初期不要填写远程模型 API Key；先单独验证核心 Board 和持久化。

### 启动与建号

```bash
npm run preflight:family
npm run family
```

浏览器访问：

```text
http://127.0.0.1:5173/
```

另开终端创建自己的账号。不给 `--password` 时会生成一次性显示的随机密码，应立即存入密码管理器：

```bash
docker compose exec gateway node scripts/create-account.js <用户名> --name="<显示名>"
```

第一个创建的账号会自动成为 owner；当前 CLI 虽能解析 `--role`，但没有把该参数传给账号存储，因此不要依赖它指定角色。

检查服务：

```bash
docker compose ps
curl -fsS http://127.0.0.1:5173/health
curl -fsS http://127.0.0.1:5173/api/health
curl -fsS http://127.0.0.1:5173/api/readyz
```

### 3–7 天自测清单

- [ ] 创建真实目标和步骤，刷新页面后仍存在。
- [ ] 停止再启动整套服务，账号、Board 和日记仍存在。
- [ ] 重启电脑后再次启动，数据仍存在。
- [ ] 未配置模型 Key 时，核心记录流程不依赖互联网。
- [ ] Gateway 或 Redis 暂停时，界面显示明确错误或降级，不伪装成空 Board。
- [ ] 做一次冷备份，并在隔离目录完成一次恢复登录。
- [ ] 记录启动、关闭、恢复和故障处理耗时，补齐看不懂的提示。
- [ ] 确认任何教程、Demo 或测试数据都没有写入或覆盖真实 Board。

停止服务但保留数据：

```bash
npm run family:stop
```

不要删除 `.stepview-family-data`，也不要把 `docker compose down` 和“清空数据”等同。任何清理动作都必须先有可恢复备份。

### 完全断网运行

首次准备仍需联网完成镜像拉取和前端构建。镜像已经成功构建后，断网场景使用已有镜像启动：

```bash
docker compose up --no-build
```

完全断网时应保持 `MEM0_API_KEY`、远程模型 Key 和远程 Base URL 为空；Agent 相关联网能力不可用是预期行为，不应静默降级成假成功。

## L1：可信局域网朋友测试 Runbook

### 适用边界

- 只允许家庭或工作室内**完全信任**的私有网络。
- 不在咖啡店、学校、共享办公或访客 Wi-Fi 上测试。
- 不做路由器端口转发、DMZ、UPnP、ngrok 或临时公网 Tunnel。
- 当前是 HTTP，密码和 Bearer token 可能被同网段攻击者窃听；只使用测试数据，不记录不可替代的高度隐私内容。
- 每位朋友使用独立账号和独立强密码，不共享 owner 账号。

### 当前配置分裂的临时规避

在 `DEP-001` 至 `DEP-003` 完成前，不要把秘密写入 `.env`。可以用一次性进程环境变量启动，绑定机器当前明确的局域网 IPv4：

```bash
STEPVIEW_BIND_ADDRESS=<本机局域网IPv4> \
STEPVIEW_ALLOW_REGISTRATION=false \
STEPVIEW_SESSION_TTL_HOURS=24 \
npm run family
```

不要使用 `0.0.0.0`，也不要把示例 IP 原样照抄。DHCP 可能改变地址，每次测试前重新确认；长期测试可在路由器中为测试主机设置 DHCP 保留地址。

不要使用 `npm run start:family` 做朋友测试：它是开发方式，Vite 会监听 `0.0.0.0`，配置和生产容器路径也不同。

### 账号和访问

```bash
docker compose exec gateway node scripts/create-account.js <朋友用户名> --name="<朋友显示名>"
```

朋友访问：

```text
http://<本机局域网IPv4>:5173/
```

主机防火墙只允许可信私有网络或指定测试设备访问 `5173`。测试结束后运行 `npm run family:stop`。

### 局域网验收

- [ ] `5173` 只监听指定 LAN IP，不监听所有网卡。
- [ ] 其他设备可以访问 `/health` 和 `/api/readyz`。
- [ ] 宿主机和其他设备不能直连 `3210` 或 `6379`。
- [ ] 手机切到蜂窝网络后无法访问服务。
- [ ] 未建号用户不能自行注册。
- [ ] 每位朋友只能看到自己的 Board、日记、设置、Agent 会话和 API Key 状态。
- [ ] 退出登录后旧页面不能继续读写；过期会话会回到登录页。
- [ ] 多次错误密码会触发退避，错误文案不泄露账号是否存在。
- [ ] 两人同时保存时不会互相覆盖，也不会把失败显示为“已保存”。
- [ ] 容器和电脑重启后数据仍存在。
- [ ] 每日冷备份成功，最近一次恢复演练可在隔离环境登录。
- [ ] 路由器没有端口转发，公网扫描看不到 `5173/3210/6379`。

### 朋友测试规则

- 控制在 3–5 人，不用“人越多越好”替代高质量反馈。
- 明确告知：主机管理员在技术上可以读取服务器 SQLite 数据。
- 明确告知：使用 Agent 时，用户选择发送的内容可能进入所配置的模型服务。
- 给每位测试者一个反馈入口，重点收集数据丢失、串号、保存失败、无法登录和恢复问题。
- 出现跨账号访问、旧快照覆盖新数据或备份不可恢复时，立即停止测试并保留故障现场。

## 当前临时备份方案

家庭网页端目前没有覆盖全部账号的可靠在线备份入口。在 `DEP-011` 完成前，只使用**停服冷备**：

1. 运行 `npm run family:stop`，确认 Gateway 已停止写入。
2. 把整个 `.stepview-family-data` 复制到仓库之外的加密磁盘或备份目录。
3. 保留目录内的 `secret.key`；它和数据库一起决定已加密 API Key 能否恢复。
4. 记录应用版本、Git commit、备份时间、文件数量和 SHA-256 校验值。
5. `.stepview-runtime/redis` 可以额外备份，但 Redis 是可重建缓存，不是核心事实源。
6. 在独立目录、不同端口和不同 Compose project name 下恢复验证，绝不直接覆盖唯一数据副本。
7. 验证完成后再重新启动正式测试实例。

不要在线直接复制正在写入的 SQLite 主文件。临时冷备目标为每日一次、每次升级前一次、导入或大规模删除前一次。

| 阶段 | 目标 RPO | 目标 RTO | 含义 |
| --- | ---: | ---: | --- |
| L0/L1 本地 Alpha | 24 小时 | 2 小时 | 最坏丢一天测试数据，两小时内恢复 |
| L2/L3 服务器 Beta | 6 小时 | 2 小时 | 每 6 小时形成可恢复副本 |
| 付费后 | 1 小时或按承诺 | 1–2 小时 | 必须由实际恢复演练证明，不能只写在页面上 |

## L2：私有服务器预演

这一步的目标不是拉新，而是在不暴露给所有人的情况下把生产链路跑通。

### 推荐架构

```text
测试用户
  -> VPN / IP 白名单
  -> DNS
  -> Caddy :80/:443（TLS、HTTPS 跳转、安全头、边缘限流）
  -> web :8080（静态页面和同源 /api 反代）
  -> gateway :3210（仅 Compose 内网，单实例）
  -> SQLite 数据目录
  -> Redis :6379（仅 Compose 内网，可重建缓存）

gateway -> 仅允许的模型服务
备份任务 -> 加密对象存储或第二台机器
管理员 -> VPN 或限制来源 IP 的 SSH
```

服务器宿主机只应开放：

- `80/443`，由 Caddy 接收。
- SSH，使用密钥登录并限制来源；能只走 VPN 时更好。

绝不直接开放：

- Web 内部端口 `5173/8080`。
- Gateway `3210`。
- Redis `6379`。

生产环境要用独立的 Compose override：只有 Caddy 发布 `80/443`，Web 改为 `expose: 8080`，Gateway 和 Redis 只加入所需内部网络。数据路径使用类似 `/srv/stepview/data` 和 `/srv/stepview/backups` 的固定绝对目录，不依赖 Git checkout 的生命周期。

### 服务器建议

前 5–30 位邀请用户：

- x86_64，`2 vCPU / 4 GB RAM`。
- `40–80 GB` NVMe/SSD，并支持磁盘快照。
- Ubuntu LTS 或 Debian stable。
- 单 Gateway、单 SQLite 写实例。
- 不需要 GPU、Kubernetes、负载均衡或托管 Redis。

`2 GB RAM` 在预构建镜像且低并发时可能够，但 `4 GB` 更能承受迁移、备份、突发 Agent 请求和系统更新。生产服务器不应现场 `npm ci` 和构建镜像，而应拉取经过 CI 验证、带版本和 digest 的不可变镜像。

### 粗略预算

以下仅用于预算，不是供应商报价；流量、地区、税费和模型费用会明显改变结果。

| 阶段 | 配置 | 粗略成本 |
| --- | --- | ---: |
| 本机/LAN Alpha | 现有电脑 + Docker | 增量约 ¥0/月 |
| 5–30 人邀请 Beta | 2C4G、40–80 GB、对象存储 | 约 ¥60–200/月 |
| 30–150 人单机 | 4C8G、80–160 GB、更多备份 | 约 ¥150–500/月 |
| 更高可用阶段 | 主机 + 冷/热备 + 托管组件 | ¥500/月以上 |

域名通常约 ¥50–150/年，TLS 可由 Caddy 免费自动签发；早期对象存储通常是每月数元到数十元。若平台替用户承担 AI 费用，AI 很可能远高于服务器费用，因此 Beta 优先 BYOK，或为每个账号设置严格额度和熔断。

### 地区选择

| 方案 | 优点 | 代价与注意事项 |
| --- | --- | --- |
| 中国大陆节点 | 国内访问通常更稳定 | 公网域名通常涉及 ICP 备案及其他合规要求，应向供应商和专业人士确认 |
| 中国香港 | 上线快、离大陆近 | 跨境网络波动、数据所在地和供应商条款需评估 |
| 新加坡/日本 | 云服务选择多 | 大陆访问质量需真实设备实测，延迟和跨境数据需说明 |

早期可用香港、新加坡或日本做小规模邀请制验证，是否长期使用必须由真实访问质量、成本、数据政策和模型供应商区域限制共同决定。此处不是法律意见；开放注册或收费前应完成适用地区的合规核查。

域名建议使用 `app.example.com`。切换前 DNS TTL 可设为 300 秒，稳定后再提高。没有验证 IPv6 防火墙前不要发布 AAAA 记录。初期优先 DNS-only，暂不叠加多层 CDN/代理，避免真实 IP、SSE 和可信代理链变复杂。

## L3：邀请制公网 Beta

开放方式：

- 继续关闭网页公开注册，由管理员建号或使用一次性邀请码。
- 首批 5 人，稳定后逐批加到 10、20、50 人，不一次性全开。
- 每批至少观察 3–7 天：错误率、备份、磁盘、恢复能力和支持请求均正常才扩批。
- 页面明确标注 Beta、数据位置、模型出站、备份保留和服务可用性预期。
- 为安全问题、数据恢复和账号问题提供独立联系入口。

公网 Beta 的核心不是“服务器能打开”，而是发生失误后能发现、限制影响、恢复并向用户解释。

## L4：扩大开放之前

只有同时满足以下条件，才考虑开放注册、收费或扩大投放：

- 连续 30 天无已知数据丢失、跨账号访问或不可恢复事故。
- 最近一次全新环境恢复演练不超过 30 天。
- 备份成功率 100%，失败会在约定时间内告警。
- 账号禁用、密码重置、全部会话吊销和数据删除流程可执行。
- AI 成本、服务器成本、支持时间和退款成本有账号级数据。
- D7、W2S 或周回顾留存已证明，不是只靠朋友人情使用。
- 隐私政策、服务条款、数据导出/删除、滥用处理和客服边界已经明确。
- 容量压测显示当前单机至少有 2 倍余量。

在 SQLite、内存 Context 和单 Gateway 仍满足容量时继续单机。只有出现明确的多实例、可用性或数据库瓶颈证据，才评估 PostgreSQL、外部缓存或水平扩容。

## 公网前工程任务

### 配置与密钥

## 服务器安全基线

- [ ] 使用非 root 部署账号；SSH 只允许密钥登录，关闭密码和直接 root 登录。
- [ ] 防火墙默认拒绝，只开放 `80/443` 和受限 SSH；同时检查 IPv4 与 IPv6。
- [ ] 系统安全更新、时间同步和重启窗口有明确策略。
- [ ] 数据、备份和日志目录权限最小化；生产 secret 文件权限限制为仅部署账号可读。
- [ ] 容器设置 `no-new-privileges`、能力裁剪、资源上限和日志大小/文件数上限。
- [ ] Edge、应用和缓存使用分离的 Docker 网络；Redis 只允许 Gateway 访问。
- [ ] 正常同源部署保持 CORS 为空，不用 `*` 解决配置问题。
- [ ] 从外部网络执行端口扫描，确认只有预期端口可达。
- [ ] 云厂商安全组和主机防火墙同时收敛，不依赖其中单独一层。
- [ ] 生产数据目录与源码目录分离，重新部署或删除 checkout 不影响用户数据。

## 备份保留建议

公网 Beta 使用 3-2-1 原则：至少 3 份副本、2 种介质、1 份异地。

| 类型 | 建议频率 | 建议保留 | 说明 |
| --- | ---: | ---: | --- |
| 本机一致快照 | 每 6 小时 | 7–14 份 | 快速恢复常见误操作 |
| 异地加密日备 | 每日 | 30 天 | 与生产账号和磁盘故障域分离 |
| 异地周备 | 每周 | 8 周 | 防止问题晚发现 |
| 异地月备 | 每月 | 12 个月 | 是否长期保留需与隐私承诺一致 |
| 升级前快照 | 每次发布 | 最近 2–3 个版本 | 与镜像 digest、schema 版本绑定 |

备份成功的定义不是“上传命令退出 0”，而是：文件齐全、校验通过、可用正确密钥解密、SQLite 完整性通过，并且最近一次恢复演练能登录和读取数据。

## 监控与告警

### 最小监控面板

- 可用性：`/health`、`/api/readyz`、首页加载和登录烟测。
- 请求：总量、p50/p95 延迟、4xx/5xx、SSE 断开和超时。
- 主机：CPU、内存、磁盘空间、inode、I/O 和系统负载。
- 容器：状态、重启次数、OOM、镜像版本和启动时间。
- 数据：数据库大小、写入失败、锁等待、完整性检查和最近迁移版本。
- 备份：最近成功时间、大小变化、校验状态、异地状态和最近恢复演练日期。
- 安全：登录失败、429、账号禁用、异常来源和会话吊销。
- 成本：每账号模型请求、Token/金额估算、月预算和异常突增。

### 初始告警阈值

| 事件 | Warning | Critical |
| --- | --- | --- |
| readyz | 连续失败 1 分钟 | 连续失败 2 分钟 |
| 5xx 比例 | 5 分钟 > 1% | 5 分钟 > 5% 或持续增长 |
| 磁盘空间 | 剩余 < 20% 或 < 10 GB | 剩余 < 10% 或 < 5 GB |
| 容器重启 | 10 分钟内 1 次 | 10 分钟内 ≥ 3 次 |
| Beta 备份年龄 | > 6 小时 | > 12 小时 |
| TLS 证书 | 剩余 < 30 天 | 剩余 < 14 天且续签失败 |
| AI 月预算 | 使用 70% | 使用 90%，100% 自动熔断 |

阈值上线后根据实际基线调整，不能为了“没有告警”把阈值调到失去意义。

## 更新与回滚 SOP

1. CI 运行测试、构建版本镜像并记录 tag、commit 和 digest。
2. 在 staging 用生产数据的脱敏副本验证，不使用真实用户空间做 Demo 或 smoke test。
3. 生产进入短维护状态，停止新写入。
4. 对全实例做一致性备份并完成校验。
5. 拉取镜像，停止旧 Gateway；不并行运行两个 SQLite 写实例。
6. 启动新版本，等待 `/api/readyz`。
7. 使用独立 canary 账号验证登录、读取、创建、保存和重启；不写入或覆盖任何真实用户 Board。
8. 观察 15–30 分钟错误率、延迟、磁盘和日志，再结束维护。
9. 无 schema 变化时可切回旧镜像；有不兼容迁移时必须同时恢复部署前数据库。
10. 保留最近两个已验证镜像及对应备份，发布记录写明升级和回滚证据。

## 从本机迁移到服务器

1. 冻结本机写入并运行 `npm run family:stop`。
2. 对整个 `.stepview-family-data` 做冷备，记录校验和、版本和文件清单。
3. 将数据库副本和 `STEPVIEW_SECRET_KEY`/`secret.key` 通过不同安全通道传输或保管。
4. 服务器先部署与本机相同的 StepView 版本，不边迁移边升级。
5. 把数据恢复到服务器的新目录，权限授予非 root Gateway 用户。
6. 只通过 VPN 或本机端口转发启动，检查 `/api/readyz`。
7. 验证所有账号可登录且各自 Board、日记、设置和 Key 状态正确。
8. 完成一次写入、重启和再次读取，再开放给测试者。
9. 原本机目录只读保留至少 30 天；确认服务器备份和恢复演练成功后再决定归档。
10. 迁移完成后再单独安排版本升级，不把两种风险叠在同一次窗口。

Redis 只存可重建缓存，不应成为迁移成败的核心依赖；真正必须保全的是全部 SQLite 数据、清单和密钥。

## 测试矩阵

| 领域 | 必测场景 |
| --- | --- |
| 账号 | Owner/Member 登录、错误密码退避、注销、过期、改密、重置、禁用和全部会话吊销 |
| 隔离 | Board、日记、设置、API Key、Agent 会话和备份彼此不可见 |
| 持久化 | 创建→保存→重启 Gateway→重启整套 Compose→重启主机后仍存在 |
| 并发 | 两标签页、两设备和多用户同时保存；旧快照不能覆盖新版本 |
| 备份 | 全账号一致快照、校验、异机恢复、错误密钥、损坏文件和单账号恢复 |
| 升级 | 旧 schema 升级、迁移中断、磁盘满、旧镜像+旧库回滚 |
| 网络 | 断网重连、SSE 中断、Gateway 502、Redis 降级、会话过期 |
| 浏览器 | Chrome、Edge、Safari、手机窄屏、刷新和清理 localStorage |
| 安全 | 外部端口、CORS、XFF 伪造、XSS 文本、SSRF、超大请求和日志脱敏 |
| 性能 | 5–10 人并发、100/500/2000 节点、连续拖动、日记写入和备份耗时 |

## 故障演练

- 杀掉 Gateway：自动恢复；已确认保存的数据不丢，未完成请求明确失败。
- 停止 Redis：readyz 显示 degraded，Board 和日记仍可工作；若目前启动被硬阻塞则记录并修复契约。
- 数据目录只读或磁盘低于阈值：readyz 失败，UI 不显示空 Board 或“已保存”。
- 使用错误密钥：Board 不受损，API Key 解密明确失败；换回正确密钥后恢复。
- 制造迁移失败：停止新版本，恢复部署前数据库，再启动旧镜像。
- 损坏数据库副本：先保留故障现场，再恢复到新目录验证，不在原文件上反复试错。
- 异地备份不可用：本地快照继续保留并告警，任务不能静默标记成功。
- 模拟单账号误删：优先恢复该账号，不为救一个账号回滚所有人的数据。

## Go / No-Go 门槛

### L0 → L1

- [ ] 默认本机模式连续使用 3–7 天，无已知数据丢失。
- [ ] 冷备份已在隔离目录恢复并成功登录。
- [ ] 注册关闭，每位朋友都有独立账号。
- [ ] 明确绑定 LAN IP，防火墙收敛，无路由器端口转发。
- [ ] `3210/6379` 对其他设备不可达。
- [ ] 已向测试者说明 HTTP、管理员可见性和模型出站风险。

### L1 → L2

- [ ] `DEP-001` 至 `DEP-004`、`DEP-011`、`DEP-012`、`DEP-020` 完成。
- [ ] 2–5 人连续使用至少 2 周，无跨账号、静默覆盖或不可恢复问题。
- [ ] 数据增长、并发和备份耗时有基线。
- [ ] 服务器、域名、地区和预算已经确定。

### L2 → L3

- [ ] 所有 P0/L2 前任务完成。
- [ ] HTTPS、防火墙和外部端口扫描通过。
- [ ] 全账号异地备份和全新服务器恢复通过。
- [ ] 部署、迁移和回滚各演练至少一次。
- [ ] 连续 7 天私有预演稳定，告警能真实送达负责人。

### L3 → L4

- [ ] 所有 P0/L3 前任务完成。
- [ ] 最近 30 天无数据丢失、越权或密钥泄露。
- [ ] 账号运维、隐私、数据删除和事故通知流程可执行。
- [ ] 容量有 2 倍余量，AI 成本有硬上限。
- [ ] 留存与付费证据成立，扩大开放不是为了掩盖低留存。

### 立即 No-Go

以下任一情况出现，都停止扩批或发布：

- 跨账号读取、免密切换、会话吊销失效或 SSRF 可利用。
- 写入失败却显示“已保存”，或旧快照覆盖新数据。
- 备份无法在空环境恢复登录。
- 迁移失败后无法恢复旧版本。
- 生产密钥缺失、泄漏或灾难恢复时不可获得。
- 公网可以直连 Web 内部端口、Gateway 或 Redis。
- HTTPS、磁盘、日志轮转、备份和恢复告警未配置。
- Demo、模板或教程写入、替换或覆盖用户 Board。

### 0–30 天：本机与局域网
