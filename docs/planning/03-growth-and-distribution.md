## P2：分享与自然增长飞轮

### 做“值得分享但默认私密”的成果

- [ ] 支持把一段旅程导出为图片、PDF、Markdown 和只读文件；不要求注册云账号。
- [ ] 分享前必须预览，默认隐藏日记正文、姓名、精确日期、账号、文件路径和 Agent 对话。
- [ ] 提供匿名化选项：日期改为相对时间、目标名打码、隐藏未选节点、移除元数据。
- [ ] 导出卡片带低调 StepView 品牌与可移除水印，不破坏用户作品感。
- [ ] 跟踪“成功导出后主动分享”的比例，不跟踪私人正文。
- [ ] 访谈验证用户愿意分享的是完成结果、过程转折、周回顾还是模板，再决定主分享形式。

### 模板与内容增长

- [ ] 模板库先做 5 个高质量场景：学新技术、毕业作品、求职准备、30 天创作、个人项目发布。
- [ ] 模板始终是独立只读预览；用户确认后复制成新空间，绝不写入现有 Board。
- [ ] 模板强调“如何记录过程”，不要退化成任务清单。
- [ ] 支持用户导出自己的模板，默认剥离日记、日期、身份和附件。
- [ ] 用真实用户旅程做内容：起点—卡点—绕路—完成，而不只发功能截图。
- [ ] 建立可搜索的落地页，每个场景有真实 GIF/短视频和清晰下载入口。

### 发布与社区

- [ ] README 首屏改为普通用户导向：一句价值、3 张真实截图、30 秒演示、立即下载、数据隐私承诺。
- [ ] 将开发、自托管、架构和 Agent 文档移到清晰的 docs 导航，不让普通用户先读部署说明。
- [ ] GitHub Release 提供平台明确的安装包、版本说明、校验和、已知问题和回滚方式。
- [ ] 建立轻量反馈入口：建议、问题、数据恢复求助分开；自动附带脱敏版本信息。
- [ ] 每月邀请 5–10 名真实用户做回顾访谈，维护“原话库”和流失原因列表。
- [ ] 建立社区展示前先制定隐私规则、内容举报和删除机制；不自动上传任何 Board。
- [ ] 选择 1–2 个主渠道连续实验 8 周，不同时铺满所有平台。
- [ ] 发布节奏围绕用户价值故事，不以“新增 20 个功能”作为主卖点。

### 三套传播主张

#### 传播版本 A：项目过程可视化（高意图获客，优先）

- 主标题：`你的长期项目，不该只剩“完成/未完成”。`
- 内容结构：混乱的零散记录 → StepView 路径 → 一段真实项目回顾。
- 最适合人群：自学者、独立开发者、写作者、毕业设计和长期创作人。
- 最适合渠道：小红书、Bilibili、V2EX、即刻、GitHub、Product Hunt、开发者社区。
- CTA：`下载后，先记录你已经走过的第一步。`
- [ ] 制作 3 个真实案例：学会 React、独立产品发布、毕业作品完成；全部使用独立演示数据。
- [ ] 用激活和 D7 判断效果；技术社区的 Star 不能替代产品使用。

#### 传播版本 B：温柔反焦虑（扩大认知）

- 主标题：`你其实一直在走。`
- 内容结构：待办每天归零造成挫败 → 小进展被遗忘 → 回看后发现自己已经走很远。
- 最适合人群：被打卡和效率工具压累、但仍想温和成长的人。
- 最适合渠道：小红书、抖音、微博、生活方式播客、心理/成长类创作者。
- CTA：`不用补昨天，记下今天真实发生的一步。`
- [ ] 避免借焦虑营销反过来制造焦虑，不做“别人一年走了 1000 步”的比较榜单。
- [ ] 评论与访谈观察用户是否感到被理解，而不是只统计情绪内容的点赞。

#### 传播版本 C：Local-first 数据主权（信任转化）

- 主标题：`你的成长记录，应该真正属于你。`
- 内容结构：私人记录的担忧 → 本地保存/完整备份/可读导出 → 随时离开。
- 最适合人群：隐私敏感、日记用户、开发者和长期主义者。
- 最适合渠道：GitHub、V2EX、Hacker News、Reddit、隐私与效率工具社区。
- CTA：`先离线使用，再决定是否开启任何联网能力。`
- [ ] 用可验证的架构图、数据位置和恢复演示证明，不使用“绝对安全”等无法兑现的话。
- [ ] 把隐私主张放在每套传播的信任层，不让它替代核心使用价值。

### 四个增长闭环

#### 闭环 1：记录—回顾—留存

`记录真实一步 → 路径即时变长 → 周回顾看见积累 → 想继续记录`

- [ ] 首条记录后展示路径变化和下次最小动作，不弹分享或付费墙。
- [ ] 周回顾只在有真实内容时触发；空周给“可以休息”，不制造负罪感。
- [ ] 指标：首次记录耗时、首日记录成功率、周回顾打开率、W2S、D7/D30。

#### 闭环 2：完成—导出—传播—激活

`完成/转折 → 生成隐私预览 → 用户主动分享 → 访客看到真实路径 → 用同类场景开始`

- [ ] 分享图的 CTA 指向与内容匹配的场景页，而非通用 GitHub 首页。
- [ ] 分享者可关闭品牌和追踪；不因关闭水印降低导出质量。
- [ ] 指标：导出成功率、实际分享意愿、分享访问率、访问→安装、安装→激活、被推荐用户 D7。

#### 闭环 3：模板—使用—再创作

`只读模板预览 → 明确确认导入新空间 → 使用并个性化 → 脱敏导出自己的模板`

- [ ] 模板 URL 直接打开预览，下载/导入前说明会创建什么，永不覆盖当前 Board。
- [ ] 优先 5 个高完成意愿模板，不追求数量。
- [ ] 指标：预览→导入、导入→首个真实修改、模板用户 D7、用户模板产出率。

#### 闭环 4：用户故事—社区认同—新故事

`征集真实旅程 → 用户确认公开范围 → 编辑成案例 → 相似用户加入 → 产生新旅程`

- [ ] 用户故事发布前逐项确认正文、姓名、日期、链接和撤回方式。
- [ ] 奖励以 Pro 时长、导出包或稿酬为主，不用排名刺激过度公开。
- [ ] 指标：案例阅读完成、案例→下载、案例来源用户激活/D7、案例撤回和隐私投诉。

### 内容系统与素材库

建立五类可持续内容，而不是只在发布日喊一次：

1. **真实旅程**：一个目标从起点、卡点、改道到完成。
2. **方法内容**：如何记录长期学习、如何做温柔周回顾、如何不被待办绑架。
3. **视觉瞬间**：零散步骤如何变成一张路径图，适合短视频/GIF。
4. **信任证明**：数据位置、备份恢复、离线使用、可读导出的真实演示。
5. **Build in public**：用户反馈如何改变产品，失败实验也公开原因。

- [ ] 建立素材包：一句定位、3 张产品图、6 秒 GIF、30 秒视频、3 分钟演示、隐私图、FAQ、品牌图标。
- [ ] 每个案例采用“人—目标—第一步—卡点—转折—结果—回看感受”结构。
- [ ] 同一案例拆成长文、短视频、对比图和 GIF，但针对渠道重写开头，不机械搬运。
- [ ] 公开截图必须使用单独演示库或获得逐项授权的用户数据；截图前自动检查姓名、路径、通知和文件名。
- [ ] 内容 CTA 只要求一个动作：记录第一步；不要同时要求关注、加群、开会员和配置 AI。
- [ ] 每周复用表现最好的问题与用户原话，停止生产不能带来激活的“自嗨开发日志”。

### 种子用户与社区启动

- [ ] 第一期只招 20–50 人，画像为正在进行至少 4 周学习/个人项目的人。
- [ ] 申请表只问当前项目、现有记录方式、最大痛点和是否愿意每周反馈，不索取私人正文。
- [ ] 设计 4 周体验：第 1 周记录一步，第 2 周处理卡点，第 3 周回看路径，第 4 周导出旅程。
- [ ] 每周提供一次 30 分钟公开答疑和一个最小提示，不做高压打卡群。
- [ ] 记录每位用户的激活、第二次记录、D7、D30、核心障碍和愿付价格。
- [ ] 创始用户权益可包括永久价格保护、专属徽标、路线图投票；不承诺所有建议都会开发。
- [ ] 群规模超过可逐人理解反馈前不扩张；早期社区目标是学习，不是制造热闹。

### 三阶段发布节奏

#### 阶段 1：问题验证 / 私测

- [ ] 用 3 套传播页招募 20–50 名种子用户，不进行大规模公开发布。
- [ ] 每周观察真实使用并修复 P0/P1；目标是 80% 能独立激活，而不是获得大量注册。
- [ ] 门槛：数据安全 P0 清零、黄金路径稳定、至少出现一批自然回访用户。

#### 阶段 2：场景发布 / 小范围公测

- [ ] 分别以“长期学习路径”和“独立项目旅程”发布，不把所有功能一次讲完。
- [ ] 邀请 5–10 位小体量、高信任创作者真实使用两周后再分享；允许他们公开缺点。
- [ ] 门槛：来源用户激活率和 D7 不低于种子用户的可接受区间，支持量可承受。

#### 阶段 3：品牌发布 / 放大

- [ ] 在安装、首次引导、导出、付费与更新均稳定后，再集中做 Product Hunt、媒体、头部创作者和应用商店。
- [ ] 发布日只讲一个用户故事、一个视觉演示和一个信任承诺。
- [ ] 预留故障页、状态页、客服响应、回滚包和热修复流程。
- [ ] 门槛：自然新增能保持激活/D7，且新增支持成本没有吞噬收入。

### 首轮 12 个增长实验

| 编号 | 假设 | 最小实验 | 主指标 | 停止/继续条件 |
| --- | --- | --- | --- | --- |
| G01 | “长期项目路径”比通用成长更能激活 | 两版首页各引流同质用户 | 真实目标+第一步 | 连续两轮无改善则停 |
| G02 | 情绪主张提高共鸣但未必提高留存 | “效率”与“脚印被看见”文案 | D7、负面反馈 | 点击高但 D7 低不采用 |
| G03 | 动图比静态截图更快解释产品 | 6 秒 GIF 对比三图轮播 | 有效下载、激活 | 只提升停留不提升激活则调整 |
| G04 | 学习模板降低空白页障碍 | 只读模板预览 vs 空白创建 | 首条真实修改、D7 | 有覆盖/误写立即停止 |
| G05 | 周回顾形成留存 | 有足迹用户随机开放回顾 | W2S、D30 | 焦虑/关闭率上升则收敛 |
| G06 | 旅程图片产生自然传播 | 隐私预览导出小范围开放 | 实际分享、推荐激活 | 隐私事件为 0 才扩大 |
| G07 | 水印强度影响分享意愿 | 无水印/低调品牌两版 | 分享率、推荐访问 | 不强制显眼水印 |
| G08 | 小体量 KOL 更能带来高质量用户 | 5 位垂直创作者真实试用 | 激活、D7、CAC | 按留存而非播放量续投 |
| G09 | Local-first 提升下载信任 | 有/无数据信任区块 | 下载、激活 | 解释过重降低理解则简化 |
| G10 | 社区挑战能形成连续记录 | 20 人 4 周温和项目旅程 | 每周记录、D30 | 依赖群提醒才活跃则不规模化 |
| G11 | 推荐奖励能促进邀请 | 奖励主题/导出包，不奖励核心功能 | 有效邀请、被邀 D7 | 垃圾邀请或作弊上升则停 |
| G12 | 创始用户预售可验证付费 | 可退款预售页 + 清晰交付日期 | 真实付款/退款 | 不用“感兴趣”替代付款证据 |

### 8 周传播执行表

- [ ] **第 1 周**：完成定位页 A/B/C、基础事件漏斗和 3 个真实演示数据集。
- [ ] **第 2 周**：招募 20–50 名种子用户；完成首次观察，不对外大推。
- [ ] **第 3 周**：发布第一个长期学习故事和 30 秒演示，修复最高频激活障碍。
- [ ] **第 4 周**：发布独立项目故事；开始周回顾和场景页实验。
- [ ] **第 5 周**：开放隐私预览导出给小样本；联系 5–10 位垂直小创作者。
- [ ] **第 6 周**：发布本地数据、备份恢复的信任内容；检查下载→激活→D7 全漏斗。
- [ ] **第 7 周**：复用最高质量案例，停止只有浏览量没有激活的渠道和内容。
- [ ] **第 8 周**：做一次小范围场景发布；依据 D7、W2S、支持成本决定扩大、迭代或暂停。

### 传播指标与预算纪律

- [ ] 漏斗统一为：曝光 → 有效访问 → 下载 → 首次打开 → 激活 → D7 → D30 → 分享/付费。
- [ ] 定义有效访问为停留并触发核心说明/下载，不使用机器人和误触流量。
- [ ] 对每个渠道计算 CAC：内容/投放/人力成本 ÷ 该渠道新增激活用户，而非 ÷ 下载。
- [ ] 订阅产品目标回本周期初始设为不超过 3–6 个月；买断产品获客成本不得吞掉首单贡献毛利。
- [ ] 付费投放只在自然渠道已证明激活和 D7 后开始；先用小额上限验证，禁止为下载量无限加预算。
- [ ] 推荐用户必须单独看 D7/D30；如果低质量，不用奖励强行提高邀请数。
- [ ] 每周公开内部增长报告：花了什么、来了谁、激活多少、留下多少、用户为何离开。
